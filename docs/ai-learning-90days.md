# 90 天执行表（可直接打勾）

配合 `ai-learning-roadmap.md` 使用。每条都是**可验收的产出**，不是"学习 XX"。

## 使用方式

- 每周只推进一条主线，别并行。
- 每条都有「完成判据」——不满足就不算完成，避免"看了视频但不会"。
- 顺序有依赖：第 3 周之前别碰 RAG，否则你不知道自己在调什么。

---

## 第 1 周 · 摸清模型的脾气

- [ ] 读 Spring AI 2.x 官方 reference 的 ChatClient 章节（英文，约 1 小时）
- [ ] 在 GmScript 里加「模型参数」面板：temperature / num_ctx / 是否开 thinking
- [ ] 用 `qwen3:8b` 和 `qwen2.5-coder:7b` 各跑 20 次同一 prompt，记录输出差异
- [ ] 写一页笔记：为什么同一 prompt 结果会变？thinking 什么时候是浪费？

**完成判据**：能不看文档解释 temperature / top_p / num_ctx 各自影响什么，并举出你实测到的例子。

---

## 第 2 周 · 结构化输出与失败处理

- [ ] 用 Spring AI 的 `entity(Class)` 让模型输出一个 Java record
- [ ] 故意给模型刁钻输入，观察解析失败的样子
- [ ] 加一层重试 + 兜底（解析失败时降级为纯文本）
- [ ] 在 GmScript 里落地：让 AI 生成脚本时返回 `{name, description, lua}` 结构体，而不是裸文本

**完成判据**：解析失败率从 X% 降到接近 0，且失败时有可读的降级行为。

> 真实场景参考：GmScript 现在是从 Markdown 里正则抠 ```lua 代码块。改成结构化输出后，
> 代码块提取就不再依赖模型的排版习惯——这是个真实的健壮性提升。

---

## 第 3 周 · Spring AI 2.x 迁移（本周最硬）

**先读官方公告再动手**：[Spring AI 2.0.0 GA](https://spring.io/blog/2026/06/12/spring-ai-2-0-0-GA-available-now)

关键事实：2.0 要求 **Spring Boot 4.0/4.1 + Spring Framework 7.0 + Jackson 3**。
你项目是 Spring Boot 3.5.16 + Jackson 2，所以这是**联动升级**，不是改个版本号。

- [ ] 通读 2.0 GA 公告 + upgrade notes（英文，约 1.5 小时）
- [ ] **先判断值不值得升**：如果只想跑通 RAG，留在 1.1.8 也行，但要知道学的是过渡 API
- [ ] 若决定升：Spring Boot 3.5.16 → 4.x，Jackson 2 → 3，逐个修编译错误
- [ ] 修配置属性：去掉 `.options` 段、改短横线风格
- [ ] `ChatMemory` → session memory（或社区 `spring-ai-session`）
- [ ] 保证三件事不回归：流式输出、thinking 分帧、请求可取消
- [ ] 跑 `mvn test` + `scripts/smoke.sh`，必须全绿

**完成判据**：`smoke.sh` 35 项全过，且流式对话在界面上逐字出字、可中途取消。

> ⚠️ 这一步大概率会卡住。卡住时看英文 release notes，别看中文博客——中文材料普遍落后。
> 卡住的过程本身就是训练：你会学会怎么读一个框架的迁移文档。

> 💡 **如果时间紧**：跳过升级，直接进第 4 周。把 RAG 跑通拿到正反馈更重要，
> 迁移可以等你有成就感了再回头做（它是苦活，不适合放在开头）。

## 第 4 周 · 向量检索入门

- [ ] 用 `nomic-embed-text` 把 100 条文本转成向量（Ollama 的 `/api/embed`）
- [ ] 手写余弦相似度，不借助任何向量库
- [ ] 理解维度、归一化、为什么必须归一化
- [ ] 用 GmScript 的 `docs/*.md` 做语料，实现"输入问题 → 返回最相关的 3 段"

**完成判据**：能解释为什么不做归一化会导致相似度失真（最好用实测数字说明）。

> 你本机装了 `nomic-embed-text` 但代码里一次没用过。这周把它用起来。

---

## 第 5 周 · 分块与召回质量

- [ ] 实现三种分块：固定长度 / 按段落 / 递归
- [ ] 对比同一批问题在三种分块下的召回命中率
- [ ] 处理中文分块的坑（按字符切会切碎词）
- [ ] 记录：哪种分块在你的语料上最好，为什么

**完成判据**：有一张对比表，能说出"为什么这种分块在这个语料上更好"。

---

## 第 6 周 · 接向量库

- [ ] 起一个 pgvector（Docker 或本地装）
- [ ] 建表、建索引（HNSW 或 IVFFlat），理解两者差异
- [ ] 把第 4-5 周的流程迁到库里
- [ ] 灌 1000 条以上数据，测查询延迟

**完成判据**：1000 条数据下，查询 P95 延迟可接受，且能说出索引类型怎么选。

---

## 第 7 周 · 混合检索 + 重排序

- [ ] 加 BM25 关键词检索（不用向量）
- [ ] 用 RRF 融合两路结果
- [ ] 对比：纯向量 vs 纯 BM25 vs 混合，各自在什么问题上赢
- [ ] 可选：接一个 reranker（BGE-reranker）

**完成判据**：能举出至少 2 个"纯向量检索失败、混合检索成功"的具体例子（比如专有名词、函数名）。

---

## 第 8 周 · 端到端 RAG + 权限过滤

- [ ] 打通：文档 → 分块 → 嵌入 → 存储 → 检索 → 拼上下文 → 生成
- [ ] **检索前**按权限过滤（不要检索后才过滤）
- [ ] 在 GmScript 里做成「知识库问答」页面，答案带出处
- [ ] 录一段演示

**完成判据**：问「怎么给脚本绑热键」，能答对且给出处文件。

---

## 第 9 周 · 建评测集（转折点）

- [ ] 攒 50 条「问题 + 期望要点」，覆盖：正常 / 边界 / 对抗（故意问不存在的）
- [ ] 写一个评测脚本，跑完输出通过率
- [ ] 接入 `mvn test`，成为回归测试

**完成判据**：改一行 prompt，能立刻看到通过率变化。

> 这一步是分水岭。90% 的转行者止步于"能跑就行"，
> 而招聘方最想看到的就是"你怎么知道它变好了还是变坏了"。

---

## 第 10 周 · LLM-as-Judge 与陷阱

- [ ] 用强模型给答案打分（1-5 分），对比人工评分
- [ ] 实测三个陷阱：位置偏见（A/B 顺序）、长度偏好（越长分越高）、自我偏好（同家族模型互吹）
- [ ] 设计缓解措施（交换顺序、控制长度、多模型投票）
- [ ] 记录：Judge 和人工的一致率是多少

**完成判据**：能说出你的 Judge 在哪些情况下不可信，以及怎么发现的。

---

## 第 11 周 · 可观测

- [ ] 记录每次调用：模型、token 进出、延迟、是否命中缓存
- [ ] 做一个简单的成本看板（本地模型成本≈电费，但要看 token 趋势）
- [ ] 接 Langfuse（可自部署）或用 Spring AI 的 observability
- [ ] 找出你的系统里最慢/最贵的那个环节

**完成判据**：能回答"一次问答消耗多少 token、延迟多少、瓶颈在哪"。

---

## 第 12 周 · 收口与包装

- [ ] 写项目 README：解决了什么问题、架构图、评测数据
- [ ] 准备 3 个面试可讲的难点（要有细节，不能是"我用了 RAG"）
- [ ] 回顾：哪一步最难？怎么解决的？（这是面试最有价值的部分）
- [ ] 投递第一批简历

**完成判据**：README 能让陌生人 5 分钟看懂你在做什么、做到了什么程度。

## 三个面试可讲的故事（提前准备）

1. **「我踩过模型能力的坑」**：`qwen2.5-coder:7b` 收到 `think:true` 直接 400。
   说明你知道不同模型能力不同，且会读错误信息定位。
2. **「我知道我的系统什么时候不可靠」**：有 50 条评测集，改 prompt 会跑回归。
   说明你有质量意识，不是 demo 工程师。
3. **「混合检索救了我的召回率」**：纯向量在函数名上失效，加了 BM25 后 recall 从 X 到 Y。
   说明你能用数据驱动决策。

## 每周固定动作

- 周五：跑一遍全部测试 + 评测集，记录数字
- 周末：写 200 字周记（学了什么 / 卡在哪 / 下周干什么）
- 每月底：回顾路线，砍掉不重要的事

**别做的事**：同时学三个框架；收藏一堆教程不看；为了学而学，不做可验收的产出。
